# Интеграции

Обязательный сценарий не обращается к сети, платным API, банковским системам и LLM. Внешние источники заменены
локальными mock-провайдерами с тем же контрактом, который понадобился бы реальной интеграции.

## Mock-провайдеры (`credit/mock-providers.ts`)

Интерфейс:

```ts
interface ExternalDataProvider {
  readonly provider: 'FNS' | 'BKI' | 'FINANCE';
  check(input: { company, application, documents, now }): { status, payload };
}
```

Результат сохраняется как `ExternalCheck { provider, status, payload, checkedAt }` для текущей попытки подачи.

| Провайдер | Payload | Логика |
|---|---|---|
| FNSMockProvider | `active`, `registrationDate`, `okved`, `source` | Синтетический реестр по ИНН → `OK`; компания из необязательного реестрового поиска → `OK`; иначе приложена выписка ЕГРЮЛ/ЕГРИП → `DOCUMENT_BASED`; иначе `NOT_FOUND` |
| BKIMockProvider | `activeDebt`, `overdueAmount`, `maxDaysOverdue`, `hasHistory`, `source` | Синтетическое бюро по ИНН → `OK`; иначе `NO_HISTORY` с нулями |
| FinancialDataMockProvider | `revenue`, `expenses`, `profit`, `currentDebt`, `period`, `source` | Синтетическая отчётность → `OK`; иначе заявленные клиентом цифры **вместе** с приложенной бухгалтерской отчётностью → `DOCUMENT_BASED`; иначе `NOT_FOUND` |

Статусы: `OK` — данные получены; `NO_HISTORY` — кредитной истории нет (нейтрально для скоринга); `NOT_FOUND` — данных
нет, решение запросит недостающее (NEEDS_INFO); `DOCUMENT_BASED` — данные взяты из документов клиента.

Тест `credit/providers-matching.test.ts` подменяет `fetch` исключением и проверяет, что провайдеры работают без сети.

### Как заменить mock реальной интеграцией

Провайдеры передаются в `ApplicationService` (`options.providers`). Реальный адаптер должен реализовать тот же
`check` и вернуть те же статусы. Для сетевых источников понадобится асинхронный вызов до открытия транзакции
обработки — сейчас этапы синхронные, потому что mock отвечают мгновенно.

## Необязательный реестровый поиск компании

`GET /api/companies/:inn` сначала ищет синтетическую или ранее сохранённую компанию. Если её нет, используется
существующий модуль `company-data`:

- `DADATA_API_KEY` — поиск через DaData (findById/party);
- иначе импортированный индекс ФНС в `FNS_DATA_DIR` (`npm run sync:fns`).

Без ключа и индекса поиск возвращает «не найдено», и клиент вводит сведения о компании вручную. Для такой компании
ФНС-проверка потребует выписку из реестра, финансы — показатели с отчётностью, а БКИ вернёт `NO_HISTORY`.
Сырой ответ реестрового поиска доступен в `GET /api/company/:inn` (503, если источник не настроен).

## Документы

Файлы читаются в браузере (`shared/document-reader.ts`: TXT, PDF, DOCX, OCR сканов через tesseract.js с локальными
языковыми данными) только для подсчёта извлечённых символов. На сервер передаются тип, имя, MIME-тип, размер и число
символов. Содержимое документов не анализируется и не хранится; для демо есть кнопка «Демо-файл».

## Чего нет

- Реальных обращений к ФНС, БКИ, банковским системам, скоринговым сервисам.
- Электронной подписи и выдачи денег: `POST /sign` только переводит заявку в `COMPLETED`.
- LLM/AI: интеграция GigaChat из предыдущей версии проекта удалена вместе с доменом мер поддержки; объяснения строятся
  детерминированно из факторов и правил.
