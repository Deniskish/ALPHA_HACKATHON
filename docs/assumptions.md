# Допущения

| Допущение | Что это значит |
|---|---|
| **Скоринг синтетический** | Факторы, веса и пороги `ScoringEngine` придуманы для демонстрации объяснимой оценки. Они не откалиброваны на данных и не предсказывают дефолт. |
| **Логика решения синтетическая** | Правила `CreditDecisionEngine` (стоп-факторы, пороги 60/75, лимит платежа 50% прибыли, долговая ёмкость 50% выручки, порог осторожности ML 0,20) — демонстрационные, а не кредитная политика банка. |
| **Ставка — иллюстрация** | Ставка = ключевая ставка (демо 16%, `CREDIT_KEY_RATE`) + маржа продукта + надбавка за риск (0/2/4 п.п.). Это не формула Альфа-Банка или другого банка. |
| **ML-модель — демо** | LightGBM обучена на сгенерированных данных; метрики показывают качество метода на этих данных. Модель не является моделью банка и не принимает решение. |
| **LLM необязателен** | По умолчанию выключен; включённый только формулирует тексты по готовому результату и проверяется. |
| **Кредитные продукты синтетические** | «Оборотный кредит», «Инвестиционный кредит», «Экспресс-финансирование», «Финансирование оборудования», «Рефинансирование», «Развитие молодого бизнеса» и их суммы, сроки, маржи вымышлены и не являются продуктами Альфа-Банка или другого банка. |
| **Интеграции ФНС/БКИ и данные банка замоканы** | Ответы ФНС, бюро кредитных историй, финансовых источников и «данные банка» о клиенте берутся из синтетического набора; сеть не используется. |
| **Подписание, выдача и платежи смоделированы** | «Подписать договор» → COMPLETED, «Получить финансирование» → ACTIVE_FINANCING, «Смоделировать платёж» отмечает платёж; подпись, договор, перевод и проводки не создаются. |
| **Выдача денег не выполняется** | Ни на одном шаге не происходит перевода средств и не создаётся кредитный договор. |
| **Демо-данные синтетические** | Компании «Демо …» вымышлены; их ИНН проходят проверку контрольной суммы, но используют неприсвоенный код региона `00`. Реальные персональные данные не используются. |
| **Это не банковская скоринговая система** | Решение демонстрирует процесс и связность клиентской и банковской сторон; использовать его для реальных решений нельзя. |

## Дополнительные допущения MVP

- **Демо-вход.** Авторизации нет; «Я клиент» / «Я пока не клиент» и выбор компании — демонстрационные и хранятся в
  `sessionStorage`. Кабинет показывает заявки выбранной компании; банковская сторона — все заявки стенда.
- **Только действующий бизнес.** Сценарий физлица, которое планирует открыть бизнес, не поддерживается.
- **Документы — метаданные.** На сервер передаются тип, имя, размер и число извлечённых символов; подлинность и
  содержание документов не проверяются.
- **Заявленные финансы** учитываются, только если во внешних источниках их нет и приложена бухгалтерская отчётность;
  для не клиента они обязательны.
- **Компания без реестровых данных** проходит проверку ФНС только с выпиской из ЕГРЮЛ/ЕГРИП; отсутствие кредитной
  истории оценивается нейтрально.
- **Возраст бизнеса** считается от даты регистрации до текущей даты сервера.
- **Одна попытка — одна оценка.** После NEEDS_INFO и повторной отправки создаются новые проверки, оценка и решение;
  прежние сохраняются в истории.
- **Синхронная обработка.** Mock-источники отвечают мгновенно, поэтому все этапы выполняются в одной транзакции;
  клиентский таймлайн проигрывает уже записанные этапы.
- **Лимит запросов** — 300 в минуту на клиента; в Docker nginx передаёт адрес клиента, API доверяет только частной
  сети compose (`TRUST_PROXY`). Лимит и `Idempotency-Key` хранятся в памяти процесса (один экземпляр API).
- **Ключевая ставка** задаётся конфигурацией, а не загружается из внешнего источника.
