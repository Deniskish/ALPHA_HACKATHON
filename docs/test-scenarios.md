| Unit: state machine | `api-server/credit/state-machine.test.ts` | Полнота таблицы, happy path, все исходы решения, NEEDS_INFO → повторная подача, запрет недопустимых переходов, финальные состояния |
| Unit: хранилище | `api-server/credit/store.test.ts` | Идемпотентный seed, сохранность на диске, номера заявок, оптимистичная блокировка, порядок событий, откат транзакции |
| Unit: провайдеры, подбор, валидация | `api-server/credit/providers-matching.test.ts` | Синтетические ИНН, работа mock без сети, NOT_FOUND → DOCUMENT_BASED, подбор продуктов и объяснения, полнота заявки, аннуитет |
| Unit: скоринг и решение | `api-server/credit/scoring-decision.test.ts` | Детерминированность и границы скоринга, сценарии A–D, MEDIUM-риск, убыток, неизвестный реестр, смена продукта во встречном предложении |
| API | `api-server/credit/api.test.ts` | Создание, изменение, документы, отправка, обработка, результат, ошибки валидации, недопустимые переходы, идемпотентность, E2E A–D через HTTP, ручная компания |
| API: инфраструктура | `api-server/app.test.ts` | Health и статус источников без внешних сервисов, удалённые legacy-маршруты, сжатие, лимит запросов и trust proxy, единые ошибки |
| Контракт | `api-server/contracts.test.ts` | DATA-API ↔ OpenAPI ↔ ответы; все маршруты Express есть в OpenAPI и наоборот; живые ответы полного сценария соответствуют схемам |
| Реестровый поиск | `api-server/company-data/*.test.ts` | Сохранённый модуль поиска компании по ИНН (DaData, импорт ФНС) |
| Frontend | `src/credit/credit-ui.test.ts` | Маршруты, форматирование сумм, отсутствие внутренних терминов в клиентских текстах, рендер результата, профиля и этапов обработки |
| Frontend: dev-сервер | `dev-server.test.ts` | Vite отдаёт общие модули и проксирует только `/api` |
| Production-сервер | `scripts/serve.test.cjs`, `scripts/restart-api.test.cjs` | Кеширование, сжатие, proxy, перезапуск API с сохранением настроек |
| Деплой | `ops/deploy.test.cjs` | Транзакционное переключение артефактов и откат |
| E2E (браузер) | `scripts/credit-e2e.check.cjs` | Сценарии A–D через интерфейс, принятие и подписание, банковская сторона, отсутствие горизонтального скролла и ошибок консоли; Chromium и WebKit, 1280 и 390 px |
| Docker smoke | `ops/docker-smoke.cjs` | `docker compose up --build`, healthcheck, frontend, 4 сценария через nginx, повторная обработка C, сохранность после перезапуска API |

Запуск:

```bash
npm test
npm run build
npm run test:production --prefix miniapp && node --test ops/deploy.test.cjs
# E2E: запустите API и frontend (README → «Локальный запуск»), затем
OPORA_UI_ENGINE=chromium,webkit npm run test:e2e
npm run smoke:docker
```

E2E-проверка делает много запросов подряд; при необходимости запустите API с `API_RATE_LIMIT=5000`.

## Негативные API-проверки

| Запрос | Ожидаемый ответ |
|---|---|
| `POST /api/applications` с `requestedAmount: -5` | 400 `VALIDATION_ERROR`, `details.field = requestedAmount` |
| `POST /api/applications/:id/submit` для неполной заявки | 422 `APPLICATION_INCOMPLETE`, `details.missing` |
| `POST /api/applications/:id/process` до отправки | 409 `INVALID_STATE` |
| `POST /api/applications/:id/accept` в DRAFT или REJECTED | 409 `INVALID_TRANSITION` |
| `PATCH /api/applications/:id` после решения | 409 `APPLICATION_LOCKED` |
| `PATCH` со старой `version` | 409 `VERSION_CONFLICT` |
| Повторный `POST /process` | 200, `replayed: true`, новых событий нет |
| Некорректный JSON или тело > 48 КБ | 400 `INVALID_INPUT` |
