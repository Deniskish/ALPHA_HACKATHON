## Обновление и проверка

Каждый источник запускается отдельно каждые 15 минут, имеет собственные очередь, курсор, кэш и статус. Перезапуск сохраняет эти данные. За проход читается до восьми страниц и выполняется до трёх новых AI-разборов на источник. При большом каталоге обход занимает несколько проходов. Фоновые запросы GigaChat имеют низкий приоритет, пользовательский чат использует существующую общую очередь.

Федеральные источники включены постоянно. Региональные — когда регион приходит в сигнале открытого профиля (`POST /api/funding/interest`, только регион). Активность региона хранится 30 дней. Первое покрытие: Чувашия, Татарстан, Москва; остальные регионы попадают в список пробелов покрытия для команды. Новый регион добавляется в реестр после проверки оператора и структуры страниц, а не через произвольный интернет-поиск.

AI извлекает название, тип меры, территорию, получателей, условия, сроки приёма и документы. Сервер проверяет схему, точные цитаты, подтверждение дат и допустимый источник. Адрес организатора не считается территорией действия. Отсутствие даты не означает бессрочный открытый приём. Неизвестные числовые параметры не заполняются догадками. Суммы, ставки и ограничения остаются в цитате условий; числовые поля новых HTML-мер пока не извлекаются автоматически.

Страницы-списки, новости и неподтверждённые результаты остаются вне опубликованного каталога. При изменении уже опубликованной страницы старая карточка остаётся доступной со статусом, требующим проверки, до нового успешного разбора. Весь текст и доказательства сохраняются на сервере, в мобильный каталог отправляются только необходимые поля.

## Дубликаты

Дубликаты определяются по нормализованным названию, оператору, типу, территории и сроку приёма; исходные ID сохраняются при обновлении известных карточек. Повторный обход или изменение версии в том же наборе фактов не создаёт вторую карточку в каталоге. Разные периоды приёма считаются разными возможностями. Произвольно похожие названия разных операторов не объединяются; сложные межсайтовые дубли с разными названиями требуют явного сопоставления в адаптере.

## Мониторинг команды

Пользовательский интерфейс не выводит ошибки импорта. Для команды предусмотрены:

- Структурированные серверные логи `event=funding_source`, ID источника и безопасный код сбоя.
- Защищённый `GET /api/internal/funding/status`, заголовок `Authorization: Bearer <OPORA_MONITOR_TOKEN>`. Без настроенного токена или с неверным токеном возвращает 404. Токен хранится только на сервере; деплой сохраняет его из PM2.
- Локальный read-only отчёт на сервере без сетевых вызовов:

```sh
OPORA_FUNDING_DIR=/path/to/persistent/funding node miniapp/api-server/funding-catalog/monitor.cjs
```

`--strict` даёт ненулевой exit code при отсутствии данных или сбоях. В отчёте: последняя попытка, последнее чтение, количество мер, неподтверждённые страницы, региональные пробелы. ИНН, названия компаний и ключи не выводятся.

Кэш `OPORA_FUNDING_DIR/official-web/*.json` и файл региональных интересов должны сохраняться между деплоями. `FUNDING_SYNC=off` отключает все фоновые импорты.

## Проверка перед публикацией

Автотесты покрывают изоляцию источников, перезапуск, изменение условий при отказе AI, цитаты и даты, неверные домены/редиректы, регионы, дубли и доступ к мониторингу. Сетевой probe подтвердил чтение пяти операторов из шести. Реальное AI-извлечение требует серверных ключей и отдельного запуска после деплоя; в локальных тестах модель заменена контролируемыми ответами.

Локальная проверка 27.09.2026: сборки API и интерфейса успешны; 155 серверных тестов, 62 теста интерфейса, 4 проверки production-сервера и 10 проверок деплоя прошли. Браузер: 320 px / светлая тема и 393 px / тёмная; новая HTML-мера доступна в каталоге, избранное сохраняется после перезагрузки, отказ сервера не удаляет кэш и не выводит технические ошибки. JavaScript-ошибок и горизонтального переполнения нет.
